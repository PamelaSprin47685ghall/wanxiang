## 决策 94：Tool 是否强制设置超时？

**AI 建议：** 不设统一强制超时，由每个 Tool 自己决定是否配置超时。原因是 Tool 的性质差异很大：
- 普通 HTTP 查询适合短超时；
- 长时间构建、下载或远程任务可能合理地运行很久；
- 人为设置统一上限容易误杀合法操作；
- 用户仍可通过取消当前 `generationId` 请求终止支持取消的 Tool。

建议规则：
- Tool 定义可以声明可选超时；
- 未声明时无限等待，直到完成、进程退出或收到取消；
- 超时、取消和异常均转换成完整 Tool Result，并单独记账；
- 如果底层 Tool 不支持真正取消，取消后允许它在后台完成，但迟到结果仍按此前规则忠实记账。

## 决策 100：达到 MCP 并发上限后如何处理新调用？

**AI 建议：** 在内存中按 FIFO 等待，不立即失败，也不持久化队列。具体语义：
- 每个 MCP 配置拥有独立等待队列；
- 有并发名额释放时，按入队顺序启动调用；
- 等待中的调用仍属于当前 `generationId`；
- 用户取消该生成时，尚未启动的调用直接移出队列，并形成取消 Tool Result；
- S 进程崩溃时等待队列丢失，符合运行时状态不持久化的既定原则；
- TOML 降低并发上限时，不中断已运行调用，只限制后续启动；
- 配置排空时，已排队但尚未启动的旧配置调用仍按旧配置执行，避免一次 Provider 响应中的同批 Tool Call 被配置更新拆分。

# 50. 自动问答 七：Tool 与 MCP（Q161–170）

**161. 问：Tool 的稳定身份如何命名？**
答：使用命名空间化稳定 ID，例如 `builtin:file.read`、`mcp:<server-id>/<tool-name>`；显示名称不是身份。

**162. 问：两个 MCP 配置能否使用同一 server ID？**
答：不能。TOML 完整验证失败，不采用后出现者覆盖前者。

**163. 问：本地 MCP 子进程能否把普通日志写到 stdout？**
答：不能。stdout 专用于 MCP 协议；普通日志必须写 stderr。

**164. 问：MCP stderr 如何处理？**
答：转发到万象 stderr，并附加 MCP 配置 ID、进程 ID 和时间；已知密钥值必须脱敏。

**165. 问：MCP 子进程环境变量是否继承全部父进程环境？**
答：默认继承必要基础环境，并叠加 TOML 显式配置；敏感环境应尽可能白名单化，而不是无条件完整复制。

**166. 问：未配置 `max_concurrency` 时是多少？**
答：不额外限流，受 MCP Server、系统资源和同批 Tool 数量约束。

**167. 问：排队中的 MCP 调用被取消时是否启动子进程？**
答：不启动，直接从 FIFO 移除并生成取消 Tool Result。

**168. 问：Tool Result 特别大时是否截断？**
答：不静默截断。超过配置的协议安全上限时产生明确失败结果；大二进制内容应使用附件引用。

**169. 问：Tool 返回二进制数据怎么处理？**
答：保存到附件内容寻址存储，Tool Result 中只保留附件引用和元数据。

**170. 问：Tool 参数解析失败是否调用 Tool？**
答：不调用。生成完整失败 Tool Result，保留原 Tool Call，并让后续 Provider 自行处理。
