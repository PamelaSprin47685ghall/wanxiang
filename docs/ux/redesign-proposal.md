# 万象 UX 重设计提案

状态：提案（待分工实施）。日期：2026-10-12。
范围：旅程、信息架构、功能、默认值、术语均可调整。不可破坏的边界见第 1 节。

前四轮 UX PR（无障碍、PWA 触屏、服务商空态、对话界面）只做了界面层的小修。
本提案不再停在控件层，改从**用户要完成的事**出发，找出旅程里该删的步骤、该合并的概念、缺失的能力和错误的默认值。

---

## 1. 不可破坏的边界

| 边界 | 出处 | 对本提案的约束 |
|---|---|---|
| 线上 AG-UI 1.0；入站未知事件宽容忽略 | `wanxiang-protocol` §55、README | 新能力只通过**加法**实现：新增 `wanxiang.dev/*` CUSTOM 事件或可选字段。旧客户端必须能忽略它们并继续工作。不改动、不删除现有事件。 |
| 落盘 RFC 7464 事件日志；只追加；删除用 tombstone；编辑即 fork | `wanxiang-store` §47、`wanxiang-chat` §35–38 | 不改日志格式，不重写历史。新增的永久事实要走单写者，并带版本号。凡需新事件类型，必须附重放测试。 |
| 不持久化运行时状态（delta、排队、取消、审批等待） | 原则 2、决策 22 | 审批等待、搜索任务、配对邀请一律只存内存。 |
| 不隐藏重试；不制造永久“错误消息” | 原则 5、规则 42 | 错误恢复只能做成**显式**重试按钮和更清楚的说明，不做自动重发。 |
| 配置只经 TOML 原子重写 | 原则 9 | 凡是改服务端设置的流程，仍走“生成完整 TOML → 原子 rename → 重读”。 |
| 同源 PWA 不自动配对 | 决策 65 | 配对仍需要 6 位码、5 分钟有效、限流。可以改的是**码从哪里拿**。 |
| Tool 默认全批准 | 决策 93 | 这是首版取舍，原文写明“未来引入权限时再单独设计”。W3 提出此设计，同时更新决策 93。 |
| UI 规范 v1（Lucide、间距阶梯、字号、无伪类手写、对比度） | `wanxiang-ui` | 新界面沿用现有 token 和控件。需要例外时先改规范。 |
| 一方文案不得出现旧名称 | `wanxiang` 总纲 | 不引入禁用名称。 |

文档同步规则：有意修改上表任一行的语义时，在同一 PR 里更新对应 skill 章节，并在 `wanxiang` 总纲新增章节记录原因。预留编号 60 起。

## 2. 现状：端到端旅程地图

下面每一步都对应当前代码。步骤数按“用户必须做出的动作”数。

### 2.1 首次运行（桌面）

1. `./start.sh`，首次构建，界面打开并**自动**连接本机服务端（桌面自动配对，决策 64）。
2. 看到空态“还没有可用的模型”，旁边有“添加服务商”。
3. 进入 设置 → 服务商 → 添加服务商 → 选预设 → 粘贴密钥 → （可选）获取模型列表 → 保存。
4. 关闭设置，回到输入框，选模型（输入框左下角），发送。

约 8 个动作。用户在第 3 步离开了对话，又要自己回来。保存成功后没有“去试一句”的落点。

### 2.2 连接服务商与选模型

- 16 个预设，`kind` 三种（openai / anthropic / gemini）。同一家有“原生”和“兼容端点”两条，用户难判断选哪个。
- 模型列表靠手动“获取模型列表”，默认值靠 `defaultModel`。
- 切模型只影响当前会话；新会话用什么模型由服务商默认决定，设置里看不到“全局默认模型”这个概念。
- 无模型时，点模型入口会直达添加服务商（上一轮已修）。

### 2.3 对话

- 新建入口有 Ctrl+N 与侧栏按钮；空态不再重复（上一轮已改）。
- 发送、排队发送、停止共用右侧。会话参数（temperature、系统指令、工具）藏在顶栏菜单“会话上下文”和输入区摘要里。
- 草稿、待确认消息只在内存里，刷新或关窗即丢（README 已声明）。
- 错误在原位显示卡片，可重试的给按钮。

### 2.4 工具调用与审批

- 全部自动批准、全部在服务端进程内执行（决策 93）。
- 界面只展示“调用 N 个工具 · 已完成”，展开后是原始 JSON 参数与结果。
- 默认可见的内置工具包含 `builtin_echo`（调试用）、`builtin_time`；文件工具只有配置了 `fileReadRoots` 才出现。**普通用户的工具列表里默认有一个调试工具，却没有任何真正有用的工具。**
- 用户无法在工具执行前看到、拒绝或限制它。MCP 工具同样自动执行，而 MCP 可以是任意本地命令。

### 2.5 历史、分叉、搜索

- 侧栏按时间分组，另有置顶、归档、多选、导出。
- 搜索只匹配标题、预览（最后一段文字）、模型名、服务商 id（`ConversationSummary.matches`）。**搜不到消息正文。**
- 分叉：只有一个 `isFork` 布尔值，行里写“分叉会话”。看不到它来自哪个会话、从哪条消息分出，也看不到同一条消息有哪些其他分叉。
- “重新生成”会作废上一轮回复（对话框说明“无法撤销”）。

### 2.6 设置

两组：当前服务器（服务商、工具与 MCP、新会话默认值）、这台客户端（外观与操作、关于）。
“服务器”与“服务商”只差一个字，屏幕上同时出现；“会话”“对话”两词混用。

### 2.7 桌面与 PWA 配对

1. 浏览器打开服务端地址，PWA 加载。
2. 点“连接”→“没有令牌？改用配对码”。
3. 提示“配对码会打印在服务端终端（stderr），5 分钟内有效。”
4. 用户必须切到运行万象的那台机器的终端，找到 JSON Lines 里的 `pairing-code` 一行，抄 6 位数字，在 5 分钟内回来输入。

**对桌面用户**（已经开着万象窗口）这一步要翻终端，而 `start.sh` 启动后终端可能早就被滚走。**对手机用户**，这是整条旅程里最难的一步。服务端已经认识桌面客户端，却不让它帮忙发码。

### 2.8 错误恢复

- 连接失败：对话框里按文案关键词（“失败”“拒绝”“断开”）判断是否显示重试，脆弱。
- 断线：草稿保留，消息进入“未确认”，可原样重试（做得好）。
- 服务端配置非法：服务端继续用旧配置，只写 stderr。**客户端界面看不到“你的配置改坏了”。**
- `doctor` 只有命令行入口。

## 3. 问题清单（按影响排序）

影响 = 受影响用户比例 × 严重度。S 级会让用户放弃，A 级会让用户绕路，B 级是长期摩擦。

| # | 级别 | 问题 | 证据 | 本质 |
|---|---|---|---|---|
| P1 | S | **首次运行要跨 4 个界面才能发出第一句话** | §2.1 | 旅程终点（发消息）与起点之间隔着“设置”这个维护区 |
| P2 | S | **PWA 配对码只出现在服务端 stderr** | §2.7；`ServerApp.fs` 第 393 行 | 已认证的桌面客户端无法替新设备发邀请 |
| P3 | A | **工具对用户不透明且无法拒绝**；默认工具是调试工具 | §2.4；`BuiltinTools.fs` | 唯一的安全模型是“信任一切”，且看不懂参数 JSON |
| P4 | A | **搜不到消息正文** | §2.5 | 历史越长，侧栏搜索越没用 |
| P5 | A | **“服务器 / 服务商”“对话 / 会话 / 分叉 / 分支”概念重叠** | §2.6；代码里“会话”约 300 次、“对话”约 74 次、“分叉”约 22 次、“分支”约 21 次 | 同一事物多个名字，不同事物相近名字 |
| P6 | A | **分叉看不到谱系** | §2.5 | 能力存在，但用户建不起“这是一棵树”的心智 |
| P7 | A | **模型选择无全局默认；服务商“原生/兼容”二选一让人困惑** | §2.2 | 用户想表达“默认用 Claude Sonnet”，概念却是“服务商的 defaultModel” |
| P8 | B | **服务端配置错误只在 stderr 出现，客户端无感知** | §2.8 | “服务端继续跑旧配置”合理，但用户以为改好了 |
| P9 | B | **草稿刷新即丢** | README | 对 PWA（手机切后台就会被回收）影响尤其大 |
| P10 | B | **工具调用展示是 JSON** | §2.4 | 面向开发者，不面向使用者 |
| P11 | B | **错误重试判断靠文案关键词** | `Dialogs.fs` 第 327 行 | 实现隐患，文案一改行为就变 |

### 3.1 可以删的步骤

- 添加服务商后“回到聊天并选模型”两步：保存成功即选定模型并落到输入框。
- 获取模型列表的单独按钮：填完密钥后自动探测，失败再给手动入口。
- 连接对话框里“令牌 / 配对码”二选一的分支：桌面本机根本不需要看到它；PWA 只需要配对码一条路。
- 抄 stderr：由已连接的客户端发码。

### 3.2 可以合并的概念

| 现在 | 合并为 | 理由 |
|---|---|---|
| 服务器（万象实例）与服务商（模型来源）同屏出现 | 实例叫“主机”，模型来源叫“模型服务” | 两个相似词指两件无关的事 |
| 会话 / 对话 | **对话** | 用户说“聊天记录”，不说 session；README 本身就写“对话” |
| 分叉 / 分支 | **分叉**（动作与关系），“版本”只用于同一条消息下的备选 | 避免“分支”与 git 的歧义 |
| “会话上下文”“生成参数”“新会话默认值” | **对话设置**（单个对话）与**默认设置**（所有新对话） | 范围一目了然 |
| 工具与 MCP | **工具**，MCP 只是工具的来源之一 | 使用者不关心协议名 |

### 3.3 缺失的能力

全文搜索；工具执行前确认；从桌面发出配对邀请；分叉谱系与兄弟分叉切换；本地草稿持久化；服务端配置错误的客户端提示；全局默认模型；一键测试连接；对工具调用的可读展示。

### 3.4 错误的默认值

| 默认值 | 问题 | 建议 |
|---|---|---|
| 内置工具含 `builtin_echo` | 调试工具暴露给用户 | 从面向用户的目录里隐藏，只在开发模式（`--dev-tools` 或 TOML `tools.exposeDebug = true`）出现 |
| 文件工具默认不注册（`fileReadRoots` 为空） | 用户永远看不到“读文件”能力，也不知道可以开 | 保持“默认不可读任何目录”（安全默认不变），但在工具页给出“授权一个文件夹”入口，写入 `fileReadRoots` |
| 新对话模型 = 服务商 defaultModel | 没有“用户的默认模型”概念 | 增加全局默认模型（见 W2），写回 TOML |
| 配对码有效期 5 分钟、仅 stderr | 手机用户来不及 | 有效期保持 5 分钟（决策 46），码改为在客户端界面展示并带倒计时 |
| 草稿只在内存 | 手机切后台即丢 | 持久化到客户端本地存储（不入日志，不同步，见 W5） |

## 4. 目标旅程

### 4.1 首次运行（目标 ≤ 4 个动作，不离开聊天界面）

```
启动 → 聊天主界面（输入框居中）
  输入区上方出现一张“连接一个模型”卡片（不是设置页）
    ① 选一家（顶部 4 个：OpenAI / Claude / Gemini / 本机 Ollama；其余折叠）
    ② 粘贴密钥 → 自动探测模型 → 自动选好默认模型
    ③ 点“试一句”→ 卡片收起，输入框预填“你好，介绍一下你自己”并聚焦
  ④ 回车
```

- 若本机 `127.0.0.1:11434` 有 Ollama 在响应，卡片直接给“发现本机 Ollama，一键使用”。
- 探测失败要说清原因（密钥无效 / 网络不通 / 端点路径错），并给“改用兼容端点”之类的下一步，而不是只写“失败”。
- 设置页的“模型服务”仍保留完整表单，用于高级配置。卡片与设置页共用同一个保存路径（同一个 `ConfigMutation`），不产生第二套行为。

### 4.2 新设备接入（目标：手机上 ≤ 3 个动作）

```
桌面：设置 → 设备 → “添加设备” → 展示 6 位码 + 地址 + 二维码 + 倒计时（5:00）
手机：扫码打开 PWA（地址已带好）→ 输入框自动聚焦的 6 位码 → 进入
```

- 无头服务端（没有桌面客户端）仍走 stderr，同时在 PWA 的配对页告诉用户“在运行万象的机器上执行 `wanxiang pair`”。
- 设备列表：名称、首次连接时间、最后在线、吊销按钮（今天只能手改 TOML 的 `revoked`）。吊销写回 TOML，沿用服务端立即断开该连接的现有行为。

### 4.3 工具调用（默认不变，可选择更谨慎）

- 默认策略保持“自动批准”，不改变现有用户体验和历史行为。
- 新增三档策略（每个工具各自设置，也可设全局）：**自动 / 首次询问 / 每次询问**。
- 执行前的审批卡片用**人话**描述：“读取 `/home/me/notes/todo.md`”，可展开看原始参数。卡片出现在对话流里原位，不是弹窗。
- 任意正在观察该对话且已追平的客户端都能决定，先到者胜（决策 93 原建议的语义）；无客户端在线时保持等待，不自动批准；断线不取消等待。
- 执行完成后的工具调用卡片改为一行摘要（“读取了 todo.md”“查询了当前时间”）加展开详情。

### 4.4 找回对话

- 搜索框同时搜**标题和消息正文**；结果显示命中片段，点击后滚动到对应消息。
- 侧栏行显示分叉标记；对话顶栏有“来自 ‘…’ 的第 N 条消息”的面包屑，可点击回到父对话。
- 在被编辑过的消息上显示 `‹ 2/3 ›`，在同一位置切换兄弟分叉，而不是去侧栏里找。

### 4.5 出错之后

- 连接问题：对话框根据**类型化的错误**（不是文案）显示重试。
- 服务端配置被拒绝：主机状态行显示“配置有误，仍在使用上一份有效配置”，点击看原因与行号。
- 设置页提供“检查主机”按钮，把 `doctor` 的结果展示出来（只读）。

### 4.6 术语表（用户可见层）

| 概念 | 用户词 | 内部词（不改代码标识符） |
|---|---|---|
| 一次聊天的完整记录 | 对话 | conversation / 会话 |
| 从某条消息长出的新对话 | 分叉 | fork |
| 同一条消息下的备选分叉 | 版本 | sibling fork |
| 万象实例（服务端） | 主机 | server |
| 模型来源（OpenAI 等） | 模型服务 | provider |
| 连接过来的手机/浏览器/桌面 | 设备 | client |
| 工具（含 MCP 提供的） | 工具 | tool / mcp |
| 单个对话的参数 | 对话设置 | session config |
| 所有新对话的参数 | 默认设置 | generation defaults |

代码标识符、协议字段、TOML 键、skill 里的“会话”一律不动；只改用户可见字符串。在 `wanxiang` 总纲的“全局术语”表补一行映射。

## 5. 工作流（可并行实施）

共同约定：

- 每条工作流一个分支（`ux/w1-…`），一个 PR，按 rebase 合并。
- 共享文件（`AppShell.fs`、`Sidebar.fs`、`ChatView.fs`、`Dialogs.fs`、`SettingsView.fs`）是冲突热点，下面按**区域**切分所有权。需要在对方区域加一个挂接点时，只加最小接线并在 PR 描述里点名。
- 凡新增线上事件，先在 W 内的“协议附录”里写事件名与载荷，再实现。事件名一律以 `wanxiang.dev/` 开头。
- 每条工作流自己带测试；不得降低现有 UI 385 / 非 UI 763 的通过数。
- 术语改动（W6）最后落地，其他流先用**新术语**写新字符串，旧字符串由 W6 统一扫。

### W1 首次运行与模型服务（对应 P1、P7，部分 P11）

**范围**
- 聊天主界面上的“连接一个模型”卡片（4.1）。
- 添加服务商后自动选定默认模型并聚焦输入框。
- 保存后自动探测模型；探测失败的类型化原因。
- 本机 Ollama 发现。
- 全局默认模型：新对话的模型取全局默认；TOML 新增 `[generation] defaultProvider` / `defaultModel`（可选键，缺省行为与现在一致，`configVersion` 升到 3，旧文件读入时迁移，且旧服务端读不了新文件的限制要在发布说明里写明）。
- 预设列表重排：常用 4 家置顶；“原生/兼容端点”合并为一个条目，由 `kind` 自动决定，高级区才可改。

**独占文件**
- `src/Wanxiang.UI/Views/SettingsProviders.fs`
- `src/Wanxiang.UI/Model/ProviderPresets.fs`
- `src/Wanxiang.UI/Model/Catalog.fs`
- 新增 `src/Wanxiang.UI/Views/OnboardingCard.fs`
- `src/Wanxiang.Server/ProviderCatalog.fs`、`ConfigMutation.fs`
- `src/Wanxiang.Config/ConfigModel.fs`、`TomlCodec.fs`（仅 `generation` 新键与版本迁移）

**共享接线（只加挂接点）**：`Views/ChatView.fs` 空态区域放卡片；`AppShell.fs` 一处模型选择逻辑。

**验收测试**
1. 新建空配置启动，UI 无任何服务商时，主界面出现卡片，设置页未被打开。
2. 在 mock 服务（`tools/mock_openai.py`）上：选 OpenAI 预设、填密钥、点击后模型列表被自动填充，默认模型被选中，输入框获得焦点且预填文本。动作总数 ≤ 4（用 headless 测试数点击/输入次数）。
3. 密钥错误、端点不通、路径错误各自给出不同的人话原因；没有一条只写“失败”。
4. `configVersion = 2` 的旧 TOML 读入后行为不变；写回时升为 3；重复读写幂等；未知键仍整体拒绝。
5. 新对话的模型 = 全局默认；删掉全局默认键后回落为服务商 `defaultModel`。
6. 保存路径与设置页相同：用同一个 `ConfigMutation` 测试夹具断言两条入口产生相同 TOML。

**风险**

## 7. 总体验收（旅程级）

在 headless + mock 服务上写端到端场景，各一条：

1. **首次运行**：空配置 → 发出第一条模型回复，用户动作 ≤ 4，不进入设置页。
2. **新设备**：桌面发邀请 → 另一连接配对成功 → 看到同一批对话。
3. **谨慎工具**：把工具设为每次询问 → 审批卡片出现 → 批准 → 结果记账 → 拒绝路径同样走通。
4. **找回**：搜索正文关键词 → 命中片段 → 点击滚动到消息 → 面包屑回父对话。
5. **恢复**：写草稿 → 杀进程 → 重启 → 草稿还在；日志无变化。
6. **术语**：全界面扫描，无旧词。

## 8. 需要负责人拍板的事项

依据原则 43，以下属于“产品体验显著不同”或“用户数据保留”，实施前确认：

4. W1：是否允许“发现本机 Ollama”这类对本机端口的探测。
5. 术语：“主机”“模型服务”“版本”三个新词是否采用（W6 只负责落地，不负责拍板）。
