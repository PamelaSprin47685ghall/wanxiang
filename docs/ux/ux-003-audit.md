# UX-003 审计与优先级

> 在 UX-001/UX-002 的“会话优先”基线上再走一遍首次接入、服务商、会话、设置与错误态。
> 不改协议、存储与服务端语义；只记录可验证的事实。

## 1. 审计发现（按优先级）

| 级别 | 发现 | 处理 |
| --- | --- | --- |
| P1 | 没有可用模型时，点输入区模型入口只弹一句“还没有可用的模型。”，且措辞与空态、发送拦截不一致，用户被留在死路上。有会话与无会话两条路径都有此问题。 | 本轮修复：统一措辞，并直接进入“添加服务商”，与空态主按钮同一出口。已加测试。 |
| P2 | 服务商表单的帮助文字写“重试次数（0-5）”，校验实际接受 0–10；用户按提示填 6 会被误导成“不合法”的反面。 | 本轮修复：提示改为 0–10。 |
| P2 | 连接弹窗用 `message.Contains "失败"/"错误"` 判断是否显示错误态（`Dialogs.fs`），依赖文案关键字，改文案会悄悄失效。 | 未改，建议后续改为显式的错误状态参数。 |
| P3 | 桌面与 PWA 共用同一套 F# UI，代码层面一致；但中文输入法、触屏键盘、真实服务商链路仍需真人走查（沿用 UX-002 未决事项）。 | 未验证。 |
