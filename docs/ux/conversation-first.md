# 会话优先的主界面

本轮允许重新组织全部 UX。唯一不变的产品主线是会话。
不引入项目、任务、工作区等新的持久化对象；不改变事件日志、协议和生成语义。

## 页面职责

侧栏负责找回会话：新建、搜索、历史、归档。底部显示连接目标和连接状态。新建入口只有一处，不在零会话空态重复。
聊天顶栏负责说明当前位置：会话标题、执行状态、会话菜单。
输入区负责下一次请求：文字、附件、模型、按需出现的自定义上下文摘要、发送或停止。完整上下文始终可以从会话菜单进入。
设置负责维护：当前服务器的配置与这台客户端的外观、操作偏好明确分组。

常用选择就近放置，深入参数按需展开。不能把“字段同属一个对象”当作全部字段应该同时露出的理由。

## 本轮有意改变的交互契约

可以输入时，空态不再重复提供“新建会话”或“开始输入”按钮，也不显示带框品牌卡。只保留起步问题和简短说明。
没有历史消息且窗口足够高时，输入区靠近画面中央；有消息后落回底部。
两种布局共用同一个输入控件，不重挂控件，不转移草稿。

顶栏不再常驻停止、分叉、会话参数和上一条／下一条按钮。
停止的主要入口在输入区。会话菜单保留分叉、导出、重命名和阅读位置；快捷键不变。
窄屏不会自动打开历史抽屉。用户明确打开或搜索后，焦点才进入抽屉。

会话上下文默认展示模型和系统指令。工具和生成参数折叠。
校验发现参数有误时自动展开；保存和取消留在滚动内容之外。

输入区只在会话存在特殊工具、系统指令或生成参数时显示上下文摘要；其他时候不常驻“上下文”按钮。
模型入口始终可见，附件入口始终可见；排队发送仅在生成过程中可见，发送/停止共用右侧位置。
快捷键、拖放提示归各自的输入框与附件按钮 HelpText/tooltip，不另占输入框下面一行。

服务器生成默认值采用明确提交。移开焦点、切换设置分区均不写服务器。
客户端偏好仍即时生效。

## 算法 W：会话布局

输入：连接状态 A、可用模型 M、会话 C、执行状态 R、窗口高度 H。

W1. 保持输入控件、草稿和附件控件的身份不变。
W2. 若未连接或没有模型，展示对应原因和处理入口。允许继续写本地草稿。
W3. 若 A、M 有效，C 无消息，且 R 未运行、未报错，进入起步布局。
W4. 若起步布局且 H 达到最低高度，分配输入区下方的弹性留白。
W5. 否则取消该留白，将输入区放在底部。
W6. 窗口变窄时只改变排列，不自动打开历史抽屉。
W7. 结束。

## 算法 P：让能力按条件出现

输入：当前会话 C、生成状态 R、草稿 D、可用模型 M。

P1. 始终提供消息输入、附件选择和模型选择。保持 D 的控件身份不变。
P2. 若 R 为运行中，显示“停止”和“排队发送”；否则显示“发送”，收起排队操作及其布局槽位。
P3. 检查 C 的系统指令、工具和生成参数。
P4. 若存在非默认设置，在输入区显示简短摘要；否则收起摘要及其布局槽位。
P5. 对所有已存在的 C，保留顶栏菜单里的“会话上下文”完整入口。
P6. 把键盘操作说明放在输入框 HelpText，把拖放说明放在附件按钮 HelpText。
P7. 当 R 结束且焦点停在被收起的运行操作上时，把焦点送回输入框。
P8. 用户选择“回到最新”后，滚动中途不要重新显示该按钮。到达底部或用户主动滚动时，结束此次回到底意图。
P9. 结束。

不隐藏能力，只隐藏没有必要常驻的控件。以上各步不产生永久状态，也不改变服务端协议。

## 算法 G：默认值编辑与提交

G1. 加载服务器目录。若表单无修改且未提交，更新字段；否则保留草稿。
G2. 用户改动字段后，增加编辑版本号，标记未保存。
G3. 焦点移动或分区切换，不提交。
G4. 明确保存时，先验证字段。失败则定位错误，不发请求。
G5. 记录服务器代次和编辑版本号，发出一次请求。待确认期间拒绝重复提交。
G6. 失败时保留输入，显示常驻失败说明，允许重试。
G7. 成功时只确认已提交版本。其后编辑仍为未保存状态。
G8. 收到较早服务器代次的回调时，不改变当前草稿。
G9. 切换服务器后保留旧草稿，但禁止提交到另一台服务器。
G10. 回到原服务器可继续编辑；明确放弃后才加载当前服务器的值。
G11. 结束。

草稿只在当前窗口保留，不承诺刷新或退出后的持久保存。
服务器并发配置仍沿用现有协议，不在 UI 内伪造版本锁或事务保证。

滚动锚点、参数校验展开、明确保存、提交期间继续编辑、切换服务器和晚到回调。
原有“顶栏按钮必须存在”和“失焦必须提交”的测试改为上述新契约；不改存储或协议黄金样本。
